# VibeKit Native — Agent Rules (Universal)

These rules apply to any AI coding agent (Cursor, Codex CLI, Cline, Windsurf, Gemini CLI, Aider, Continue, Cody, Junie) working inside a VibeKit Native project.

# Build Expo / React Native Apps Using the VibeKit Native Framework

## When to Apply

These rules apply when:
- The project root contains `master_prompt.md`, `vibekit-native-components.md`, or `project-phases.md`
- The user pastes a `prompt.md` generated by the VibeKit Native planning workflow
- The user explicitly asks to "build with VibeKit Native"

## Before You Write Code

Read these five framework files at the project root, in this exact order:

1. **`master_prompt.md`** (or `CLAUDE.md`) — Absolute coding rules, tech stack, full patterns for Prisma v7, Better Auth, Expo API Routes, DGateway, Stripe.
2. **`design-style-guide.md`** — Per-project visual system. Color tokens, typography, spacing, component specs. Overrides the generic design rules.
3. **`vibekit-native-components.md`** — Component registry reference. Install components with `npx vibekit-native install <name>` BEFORE building from scratch.
4. **`project-description.md`** — App spec, data model, screens, API routes, integrations.
5. **`project-phases.md`** — Phased build plan. Work through phases IN ORDER, STOP between phases.

If any file is missing, stop and tell the user to run the planning workflow first.

### Registry-First

Before writing auth, payments, chat, dashboard, navigation, commerce, or UI primitives from scratch, check `vibekit-native-components.md` and install via `npx vibekit-native install <name>`.

The CLI auto-installs native dependencies. Common installs:

```bash

npx vibekit-native install payments      # 7 payment components (DGateway + Stripe)
npx vibekit-native install commerce      # 10 commerce components
npx vibekit-native install chat          # 4 chat components
```

### Root Navigator + Auth Gate

`app/_layout.tsx` is the canonical auth gate. Reads `authClient.useSession()`, redirects signed-in to `(tabs)`, signed-out to `(auth)/sign-in`. NEVER build a marketing landing page as the root unless `project-description.md` says so.

### Prisma v7 + Neon HTTP Adapter

```ts
// src/lib/prisma.ts
import { PrismaClient } from '@prisma/client';
import { PrismaPg } from '@prisma/adapter-pg';

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL! });
export const prisma = globalThis.__prisma ?? new PrismaClient({ adapter });
```

Use the new `prisma-client` generator (NOT `prisma-client-js`).

### Better Auth + Expo Plugin

- Server: `src/lib/auth.ts` with `prismaAdapter` + `expo()` plugin + trusted origins including the app scheme
- Mobile: `src/lib/auth-client.ts` with `expoClient()` + `expo-secure-store`
- Route handler: `app/api/auth/[...auth]+api.ts` — exports `GET = handler; POST = handler`

Every protected API route calls `auth.api.getSession({ headers: request.headers })` and returns 401 on missing session.

### API Routes — Expo API Routes

Routes live at `app/api/**/+api.ts`. Export named methods (`GET`, `POST`, `PATCH`, `DELETE`). Use cursor pagination:

```ts
export async function GET(request: Request) {
  const session = await auth.api.getSession({ headers: request.headers });
  if (!session) return Response.json({ error: 'Unauthorized' }, { status: 401 });

  const url = new URL(request.url);
  const cursor = url.searchParams.get('cursor') ?? undefined;
  const limit = Math.min(Number(url.searchParams.get('limit') ?? 20), 50);

  const items = await prisma.post.findMany({
    where: { userId: session.user.id },
    take: limit + 1,
    ...(cursor && { cursor: { id: cursor }, skip: 1 }),
    orderBy: { createdAt: 'desc' },
  });

  const hasMore = items.length > limit;
  return Response.json({
    data: hasMore ? items.slice(0, -1) : items,
    nextCursor: hasMore ? items[items.length - 1].id : null,
  });
}
```

### Forms — react-hook-form + Zod (No Exceptions)

Every form. Zod schemas live in `src/lib/schemas/<resource>.ts` and are imported by BOTH the form AND the API route.

- Currency inputs: registry `<Input variant="currency">` (auto-formats while typing)
- Selects with >5 options: registry `<SearchableSelect>` (NEVER native `<Picker>`)
- Date inputs: `@react-native-community/datetimepicker` (NEVER plain text input)
- Submit buttons: disabled while submitting, `try/finally` wrapping the await, haptics on success + error

### DGateway Pattern (Mobile Money)

Mobile NEVER calls DGateway directly. Server proxy at `app/api/checkout/start+api.ts` adds the `X-API-Key` header. Webhook at `app/api/webhooks/dgateway+api.ts` verifies HMAC-SHA256 with `crypto.timingSafeEqual` (constant-time). Idempotent dedupe by `reference`.

### Stripe Pattern

`<StripeProvider publishableKey="pk_test_…">` at app root. Server mints PaymentIntent / Subscription, returns `{ clientSecret, ephemeralKey, customer }`. Mobile uses registry `<StripePayButton>` or `<StripeSubscriptionButton>`.

### Selected States — LOUD

Selected: `border-2 border-accent bg-accentLight` + filled icon. Unselected: `border border-border bg-bgElevated` + outline icon. Visible at 2 metres from a phone.

### Image-First 80/20

Use `expo-image` (NEVER `Image` from `react-native`). Empty states, onboarding, hero, stat cards, marketing banners use illustrations / photos. Ionicons reserved for inline UI affordances.

### Motion — Reanimated Only

`react-native-reanimated` 3. NEVER `Animated` from `react-native` (JS thread). ALWAYS respect `useReducedMotion()`. Timings: 150ms press, 250ms state, 400ms entrance, 600ms hero.

### Haptics

`expo-haptics` on every primary CTA, form submit success/error, swipe-to-delete.

### Touch Targets

44 × 44 pt minimum. Use `hitSlop` when visual size is smaller.

### Safe Area

`SafeAreaView` from `react-native-safe-area-context` (NEVER from `react-native`).

### Dark Mode

VibeKit Native registry is DARK-ONLY by default. Light mode = per-screen work. Only do it if `project-description.md` → Dark mode: Both.

### Env Files

ALWAYS create BOTH `.env.example` AND `.env.local` in Phase 1. Server secrets (`DATABASE_URL`, `BETTER_AUTH_SECRET`, `DGATEWAY_API_KEY`, `STRIPE_SECRET_KEY`) NEVER prefixed with `EXPO_PUBLIC_`. Production secrets via `eas secret:create`.

### Build Process — Phase by Phase

Work through `project-phases.md` IN ORDER. STOP between phases. Confirm with user.

- **Phase 1 — Foundation:** Expo init, NativeWind, expo-router, Prisma + Neon, Better Auth + Expo plugin, EAS init, Sentry init, root auth gate, `.env.example` + `.env.local`
- **Phase 2 — Core screens:** `npx vibekit-native install <categories>`, build screens with mock data
- **Phase 3 — API Routes:** CRUD `+api.ts` per entity, Zod-validated, cursor-paginated. Wire TanStack Query hooks.
- **Phase 4 — Polish:** Reanimated entrance, expo-haptics, expo-notifications, expo-linking, empty/error/skeleton states, splash + adaptive icon
- **Phase 5 — Deploy:** Prisma migrate deploy, EAS secrets, `eas deploy --prod`, `eas build`, `eas submit`, run `pre-deploy-review.md`

### Dependency Blocklist

NEVER: `@react-native-async-storage/async-storage` for primary data, `react-native-vector-icons`, `react-native-fast-image`, raw `react-navigation`, `axios`, `moment`, `lodash`, `redux`, `react-native-elements` / `react-native-paper`, `Animated` from `react-native`.

### Editing vs Replacing

When a registry install would overwrite existing work, EDIT the file to merge — never wholesale replace.

### Code Quality

- TypeScript strict mode
- No `any` (use `unknown` + narrowing)
- No `as` casts unless interfacing with untyped libs
- Extract business logic out of screens — into `hooks/` or `lib/`
- Shared Zod schemas in `src/lib/schemas/`
