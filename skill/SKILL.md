# VibeKit Native — Build with the Framework

## When to Use

Fire this skill when:
- The user opens a project containing `master_prompt.md`, `vibekit-native-components.md`, or `project-phases.md` at the root
- The user pastes the contents of `prompt.md` (generated by the planning session at claude.ai)
- The user explicitly invokes `/vibekit-native` or asks you to "build with VibeKit Native"
- The user is building an Expo / React Native app and mentions VibeKit Native

## Before You Write Any Code

Read these five framework files at the project root, in this exact order:

1. **`master_prompt.md`** (or `CLAUDE.md` if renamed) — Absolute coding rules: tech stack, Prisma v7 + Neon HTTP adapter, Better Auth + Expo plugin, expo-router structure, performance budget, form rules, image-first rule, dependency blocklist.
2. **`design-style-guide.md`** — The customized visual design system for THIS project. Color tokens, typography scale, spacing, component specs, motion timings. Overrides the generic design rules in `master_prompt.md` where they differ.
3. **`vibekit-native-components.md`** — The component registry reference. CHECK THIS BEFORE writing auth, payments, chat, dashboard, navigation, commerce, or UI primitives from scratch. Install via `npx vibekit-native install <name>`.
4. **`project-description.md`** — What the app is, who it's for, features, data model, screens, API routes, integrations. Every decision must align.
5. **`project-phases.md`** — The 5-phase build plan. Work through phases IN ORDER. STOP between phases for user confirmation.

If any file is missing, stop and tell the user. Do not improvise — the framework files are the source of truth.

## Critical Rules (non-negotiable)

### Tech Stack — LOCKED

| Layer | Pick |
|---|---|
| Framework | Expo SDK 55+ · React Native 0.83+ |
| Language | TypeScript 5.9+ strict |
| Routing | expo-router (file-based) |
| Backend | Expo API Routes (`app/api/**/+api.ts`) |
| Database | Neon Postgres (HTTP driver via `@neondatabase/serverless`) |
| ORM | Prisma v7 with `@prisma/adapter-pg` |
| Auth | Better Auth + `@better-auth/expo` plugin |
| Styling | NativeWind v4 |
| Server state | TanStack Query v5 |
| Client state | Zustand |
| Storage (preferences) | react-native-mmkv |
| Storage (sensitive) | expo-secure-store |
| Forms | react-hook-form + Zod |
| Lists | @shopify/flash-list |
| Images | expo-image |
| Icons | @expo/vector-icons (Ionicons) |
| Animations | react-native-reanimated 3 |
| Payments — EA | DGateway (UGX/KES/TZS/RWF) via server proxy |
| Payments — global | @stripe/stripe-react-native PaymentSheet |
| Email | Resend (server-side) |
| Push | expo-notifications + Expo Push Service |
| Monitoring | Sentry React Native + Sentry Node |
| Build / Deploy | EAS Build · EAS Submit · EAS Update · EAS Hosting |

DO NOT swap any of these for alternatives unless `project-description.md` explicitly says so.

### Registry-First Workflow

When you need ANY of these — auth screens, payments, chat UI, dashboard widgets, commerce flows, navigation, common primitives — FIRST check `vibekit-native-components.md`. If a registry component covers it, install via:

```bash
npx vibekit-native install <component-name>
# or by category:
npx vibekit-native install auth        # all 6 auth screens
npx vibekit-native install payments    # all 7 payment components
npx vibekit-native install dashboard   # all 6 dashboard components
```

NEVER write from scratch when a registry component exists. The CLI auto-installs the native dependencies.

### Project Structure

```
my-app/
├── app/                          # expo-router routes + API routes
│   ├── _layout.tsx               # Root navigator + auth gate
│   ├── (auth)/                   # Signed-out group
│   ├── (tabs)/                   # Signed-in group
│   ├── +not-found.tsx
│   └── api/                      # Backend (Expo API Routes)
│       ├── auth/[...auth]+api.ts # Better Auth handler
│       └── ...
├── src/
│   ├── components/               # Installed via npx vibekit-native
│   ├── hooks/                    # Custom React hooks
│   └── lib/                      # auth.ts, prisma.ts, schemas/, env.ts
├── prisma/
│   └── schema.prisma
└── assets/                       # icon.png, splash.png, adaptive-icon.png
```

### Root Auth Gate (`app/_layout.tsx`)

Default behavior: if signed in → `(tabs)`, if signed out → `(auth)/sign-in`. NEVER build a marketing landing page as the root unless `project-description.md` → "Public landing page: Yes". See `master_prompt.md` → ROOT NAVIGATOR for the canonical code.

### Prisma v7 + Neon HTTP Adapter

```ts
// src/lib/prisma.ts
import { PrismaClient } from '@prisma/client';
import { PrismaPg } from '@prisma/adapter-pg';

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL! });
export const prisma = globalThis.__prisma ?? new PrismaClient({ adapter });
```

Use the new `prisma-client` generator (NOT `prisma-client-js`). See `master_prompt.md` → PRISMA V7 RULES for the schema template.

### Better Auth + Expo Plugin

- Server: `src/lib/auth.ts` with `prismaAdapter` + `expo()` plugin
- Mobile: `src/lib/auth-client.ts` with `expoClient()` plugin + `expo-secure-store`
- Route: `app/api/auth/[...auth]+api.ts` — single file, exports `GET = handler; POST = handler`

See `master_prompt.md` → BETTER AUTH PATTERN for the complete code.

### DGateway (mobile money) Pattern

The mobile app NEVER calls DGateway directly. It calls YOUR backend, which proxies with the API key. Webhook must verify HMAC-SHA256 with `crypto.timingSafeEqual`. See `master_prompt.md` → DGATEWAY PATTERN for the complete server + client code.

### Forms — react-hook-form + Zod

Every form. No exceptions. Zod schemas live in `src/lib/schemas/` and are imported by BOTH the form AND the API route.

### Selected States — LOUD

Selected: `border-2 border-accent bg-accentLight` + filled icon.
Unselected: `border border-border bg-bgElevated` + outline icon.

The contrast must be visible at 2 metres from a phone.

### Image-First 80/20

Use `expo-image` (NEVER `Image` from `react-native`). Empty states, onboarding cards, hero sections, stat cards, marketing banners all use illustrations / photos — NOT bare icons. Ionicons are reserved for inline UI affordances (close, chevron, search, tab bar).

### Motion — Reanimated Only

`react-native-reanimated` 3. NEVER `Animated` from `react-native`. ALWAYS respect `useReducedMotion()`. Standard timings: 150ms press, 250ms state, 400ms entrance, 600ms hero entrance.

### Haptics

`expo-haptics` on every primary CTA, form submit success, form submit error, swipe-to-delete. The phone is in the user's hand — feedback is felt.

### Touch Targets

44 × 44 pt minimum. Use `hitSlop={{ top: 8, right: 8, bottom: 8, left: 8 }}` when visual size is smaller.

### Safe Area

`SafeAreaView` from `react-native-safe-area-context` (NEVER from `react-native`). `edges={['top']}` for screens with a header, `edges={['top', 'bottom']}` for full-bleed.

### Dark Mode

VibeKit Native registry is DARK-ONLY by default. Light mode requires per-screen variants — only do it if `project-description.md` → "Dark mode: Both".

### Build Process

Work through `project-phases.md` IN ORDER:

- **Phase 1 — Foundation:** Expo init, NativeWind v4, expo-router, Prisma v7 + Neon, Better Auth + Expo plugin, EAS init, Sentry init, root auth gate.
- **Phase 2 — Core screens:** Install registry categories, build all screens listed in `project-description.md` with mock data.
- **Phase 3 — API Routes:** CRUD `+api.ts` files for every entity, Zod-validated, cursor-paginated. Wire screens to TanStack Query hooks.
- **Phase 4 — Polish:** Reanimated entrance animations, expo-haptics, expo-notifications push, expo-linking deep links, empty states, skeleton loaders, splash + adaptive icon.
- **Phase 5 — Deploy:** Prisma migrate deploy, EAS secrets, `eas deploy --prod` (API routes), `eas build --profile production`, `eas submit`. Run `pre-deploy-review.md` before submitting.

STOP between every phase. Confirm with the user before moving on.

### Env Files

ALWAYS create BOTH `.env.example` (committed, placeholders) and `.env.local` (gitignored, real dev values) in Phase 1. NEVER prefix a secret with `EXPO_PUBLIC_` (would bundle into the mobile binary). Production secrets go through `eas secret:create`.

### Performance Budget — Hard Constraints

| Metric | Target |
|---|---|
| Cold start TTI (iOS) | < 2.0 s |
| Cold start TTI (Android) | < 2.5 s |
| JS bundle | < 5 MB uncompressed |
| JS + UI thread FPS | 60 fps during scroll + animation |
| API response p95 | < 500 ms |

If you exceed any budget, fix it before moving on. See `master_prompt.md` → PERFORMANCE BUDGET for fix recipes.

### Dependency Blocklist

NEVER install: `@react-native-async-storage/async-storage` (for primary data — use MMKV), `react-native-vector-icons` (use `@expo/vector-icons`), `react-native-fast-image` (use `expo-image`), `react-navigation` raw (use `expo-router`), `axios` (use `fetch`), `moment` (use `date-fns`), `lodash`, `redux` (use Zustand), `react-native-elements` / `react-native-paper`, `Animated` from `react-native`.

### Editing vs Replacing

When a registry install would overwrite a screen you've already built, EDIT the existing file to merge — do NOT wholesale replace working code. The CLI never auto-overwrites; you decide what to keep.
